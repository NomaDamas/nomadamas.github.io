# 블로그 스튜디오

블로그 글을 에이전트와 함께 쓰고 고치는 로컬 도구다. 글을 쓰는 것은 herdr 탭에 띄운 Claude Code나 Codex이고,
스튜디오는 그 진행을 보여 주고, 사람의 승인과 코멘트를 에이전트에게 전달하고, 고친 곳을 덩어리마다 수락받는다.
스튜디오 안에는 AI가 없다.

```bash
pnpm install         # 사이트 의존성
pnpm studio          # 스튜디오 의존성(studio/)을 설치하고 http://127.0.0.1:4310 을 띄운다
```

처음 켜면 설정 화면에서 두 폴더를 고른다.

| 설정                  | 무엇                                                                      | 기본값              |
| --------------------- | ------------------------------------------------------------------------- | ------------------- |
| 작업 폴더를 만들 곳   | 글마다 `<YYMMDD>-<slug>` 폴더. 요청서, 브리프, 근거 표, 캡처 원본, 코멘트 | `.studio/work`      |
| 글 worktree를 만들 곳 | 글마다 `post/<slug>`, `fix/<slug>-<YYMMDD>` worktree                      | `.studio/worktrees` |
| 에이전트를 띄울 폴더  | 비우면 작업 폴더가 든 git 저장소의 루트                                   | (비움)              |

작업 폴더는 다시 찍을 때 찾을 수 있는 곳에 둔다. 글쓰기 스킬(`nomadamas-blog`)이 든 저장소 안에 두면
에이전트가 그 저장소 루트에서 떠서 스킬과 지침을 읽는다. 설정은 `.studio/config.json`에 저장되고 git에 올라가지 않는다.
환경 변수 `STUDIO_WORK_ROOT`, `STUDIO_WORKTREE_ROOT`, `STUDIO_AGENT_CWD`, `STUDIO_HERDR_SESSION`, `STUDIO_PORT`가 있으면 그 값이 이긴다.

필요한 것: Node 24 이상(TypeScript를 그대로 실행한다), `git`, `gh`(로그인), `herdr`, `claude`나 `codex`.

## 한 바퀴

스튜디오는 아래 파일이 생기는 것으로 단계를 알아본다. 에이전트에게 주는 지시문(`task.md`)에 같은 경로가 적힌다.

| 단계         | 사람                                    | 에이전트                                   | 신호                                        |
| ------------ | --------------------------------------- | ------------------------------------------ | ------------------------------------------- |
| 새 글        | 새 글 폼을 채운다                       | (herdr 새 탭에서 시작)                     | 작업 폴더 `request.md`                      |
| 브리프       | 읽고 승인하거나 코멘트                  | 독자, 유형, 키워드, 한 문장, 절 목록, 화면 | `brief.md`                                  |
| 직접 써 보기 | 질문에 답한다                           | 설치하고 써 보며 근거와 캡처를 모은다      | `claims.md`, `captures/`                    |
| 원고         | 미리보기에 코멘트, 제안을 수락하고 커밋 | 원고와 이미지                              | 글 worktree의 `src/content/posts/<slug>.md` |
| 점검         | 빠른 점검, 빌드 점검, AI 점검 요청      | AI 점검 결과                               | `checks.json`, `ai-review.md`               |
| 발행         | push와 PR, 발행 시각, 머지              |                                            | PR이 열림                                   |
| 발행 뒤      | 사이트 확인, 공유 글 요청               | 공유 문안                                  | PR 머지, `share.md`                         |

새 글은 브리프를 승인해야 다음 단계로 넘어간다. 승인은 그때의 `brief.md` 해시에 묶여서, 승인한 뒤 브리프가 바뀌면 다시 승인을 받는다.
에이전트 쪽 30분 동안 작업 폴더와 원고가 그대로면 홈에 "멈춤"이 붙고, 글 화면에서 진행을 물어볼 수 있다.

"발행된 글 고치기"는 main에서 `fix/<slug>-<YYMMDD>` 브랜치를 따고 원고 단계에서 시작한다.

## 사람이 하는 것과 에이전트가 하는 것

- **에이전트는 커밋하지 않는다.** 고친 내용은 커밋하지 않은 변경으로 남고, 스튜디오가 `git diff`를 덩어리로 쪼개 제안으로 보여 준다.
  수락하면 그 덩어리만 stage(`git apply --cached`), 거절하면 그 덩어리만 되돌린다(`git apply -R`).
  거절한 내용은 `.studio/rejected/<글>/`에 남는다. 새 파일은 파일째 수락하거나 거절한다.
- **커밋, push, PR, 머지는 사람이 스튜디오 버튼으로 한다.** 이 요청은 스튜디오 화면에서 보낸 것만 받는다(`Origin`, `Sec-Fetch-Site` 확인).
  보안 경계라기보다 실수 방지다. 에이전트 지시문에도 이 요청을 부르지 말라고 적는다.
- 머지는 화면에서 본 PR 커밋 그대로일 때만 한다(`gh pr merge --match-head-commit`). PR 검사가 모두 통과하고,
  올리지 않은 커밋과 남은 제안이 없어야 버튼이 열린다. **머지가 곧 발행이다**(deploy.yml).
- 발행 시각은 "지금 시각으로 맞추고 커밋"으로 머지 직전 한국 시각을 넣는다(AGENTS.md "발행").

## 에이전트와 말하는 길

스튜디오는 글마다 herdr 탭을 하나 새로 열고(`herdr tab create --no-focus`) 에이전트를 띄운 뒤 한 줄만 보낸다.
"작업 폴더의 `task.md`를 읽고 진행하라". 긴 지시를 터미널에 붙이면 중간 줄바꿈에서 제출될 수 있어서다.
사용자가 쓰고 있는 탭에는 입력하지 않는다. 보낼 때마다 기록한 pane이 같은 종류의 에이전트를 돌리는지 확인한다.

에이전트 창에 폴더 신뢰 같은 확인 창이 뜨면 스튜디오는 대신 답하지 않는다. "확인 창에서 멈춤"으로 표시되고,
사람이 herdr 탭에서 답한 뒤 "지시문 보내기"를 누른다.

| 방향             | 어떻게                                                                                                     |
| ---------------- | ---------------------------------------------------------------------------------------------------------- |
| 사람 -> 에이전트 | 코멘트, 덧붙임, 질문에 대한 답, 승인 알림을 `herdr agent prompt`로 보낸다. `[스튜디오 코멘트 c3] ...` 형식 |
| 에이전트 -> 사람 | `node studio/cli.ts reply c3 "고친 것"`, `node studio/cli.ts ask "질문"`                                   |

`cli.ts`는 탭 환경 변수 `STUDIO_URL`, `STUDIO_POST`로 스튜디오와 글을 찾는다. 다른 터미널에서는 `--url`, `--post`를 준다.
에이전트용 요청은 코멘트를 읽고 답하고 묻는 것뿐이다. 브라우저가 다른 사이트에서 보낸 요청은 받지 않는다.

## 미리보기

글 worktree에서 Astro 개발 서버를 띄우고(처음엔 `pnpm install`), 그 앞에 작은 프록시를 둔다(`server/preview.ts`).
프록시는 HTML 응답에 `bridge/bridge.js` 한 줄을 끼워 넣는다. 그래서 사이트 설정을 고치지 않고도
미리보기에서 고른 문장과 이미지가 `postMessage`로 스튜디오에 전달되고, 코멘트 자리가 형광펜(CSS Highlight API)으로 칠해진다.
코멘트는 고른 문장과 앞뒤 40자로 위치를 기억해서, 원고가 바뀌어도 같은 문장을 다시 찾는다.

Astro 7은 에이전트 안에서 실행되면 개발 서버를 백그라운드로 떼어 낸다. 스튜디오가 프로세스를 들고 있어야 끌 수 있어서
Astro가 백그라운드 자식에게 주는 `ASTRO_DEV_BACKGROUND=1`을 똑같이 주고 앞에서 돌린다.

## 점검

- **빠른 점검**: 원고 파일만 읽는다. 빌드를 멈추는 규칙은 사이트의 `src/utils/checkPosts.ts`를 그대로 불러 돌리고,
  제목과 설명 길이, 본문 제목 구조, 이미지 대체 텍스트와 파일, 검색 키워드 자리, 근거 표의 빈 근거,
  `nomadamas-blog` 스킬의 지난 교정(`corrections.py check`)을 본다.
- **빌드 점검**: 글 worktree에서 `pnpm build`를 돌리고 글 페이지의 `<title>`, 설명, canonical, Open Graph, X 카드,
  `BlogPosting` 구조화 데이터, h1, `llms.txt`와 sitemap 포함 여부를 읽는다. 검색 결과와 공유 카드 모습도 그린다.
- **AI 점검**: 에이전트에게 스킬의 검수 절차(humanize-korean, patina `--backend claude-cli`)를 맡긴다.

점수는 내지 않는다. 검색 순위 점수식은 근거가 약하고, 걸린 곳마다 이유를 적는 쪽이 고치기 쉽다.

## 파일

| 경로                            | 무엇                                                                                                                      |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `server/`                       | API(Hono)와 화면(Vite + React)을 한 프로세스에서 낸다. `main.ts`가 시작점                                                 |
| `ui/`                           | 화면. 홈, 새 글, 고치기, 설정, 글(브리프, 원고, 제안, 점검, 발행)                                                         |
| `bridge/bridge.js`              | 미리보기 페이지에 끼우는 스크립트                                                                                         |
| `cli.ts`                        | 에이전트가 부르는 명령                                                                                                    |
| `.studio/`(저장소 루트, git 밖) | `state.json` 글 목록, `config.json` 설정, `runtime.json` 켜진 주소, `rejected/` 거절한 변경                               |
| 작업 폴더                       | `request.md`, `task.md`, `brief.md`, `claims.md`, `captures/`, `comments.json`, `checks.json`, `ai-review.md`, `share.md` |

`studio/`는 사이트와 따로 설치한다(`studio/pnpm-workspace.yaml`, `studio/pnpm-lock.yaml`). 그래서 루트의 `pnpm install`(배포와 PR 검사)에는
스튜디오 의존성이 들어가지 않는다. React 타입이 사이트 설치에 섞이면 satori의 `ReactNode`가 풀려 사이트의 OG 이미지 코드 타입 검사가 깨진다.
루트 워크스페이스 패키지로 두었을 때는 로컬 pnpm 11에서는 통과하고 PR 검사의 pnpm 12에서 깨졌다.
스튜디오 의존성은 이 폴더의 `package.json`에만 넣고 `pnpm --dir studio install`로 잠금 파일을 갱신한다.

```bash
pnpm studio:check    # 스튜디오 타입 검사(사이트의 astro check는 studio를 빼고 돈다)
```

사람이 켤 때만 도는 화면이다. 정해진 시각에 혼자 도는 자동화가 아니므로 저장소 지침의
"로컬 맥에 자동화를 걸지 않는다"와 부딪치지 않는다. 자동 발행(서버에서 도는 것)은 이 도구의 범위 밖이다.
