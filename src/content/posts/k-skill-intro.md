## 목차

## 에이전트가 모르는 한국 생활 정보

퇴근길에 AI 에이전트에게 "지금 강남역 2호선 언제 와?"라고 물어본다고 해 보겠습니다. 모델은 학습한 시점까지의 지식으로 답하기 때문에 지금 열차가 어디쯤 있는지는 알지 못합니다.

답이 되는 데이터는 있습니다. 서울시는 지하철 실시간 도착 정보를 서울 열린데이터 광장에서 공개 API로 제공합니다. 다만 쓰려면 인증키를 받고, 요청 주소와 응답 형식을 익혀야 합니다.

한국 생활에 필요한 정보는 대부분 이런 모양입니다. 공휴일은 한국천문연구원, 미세먼지는 에어코리아, 아파트 실거래가는 국토교통부 API에 있고, 기관마다 신청 절차와 형식이 다릅니다. 한글(HWP)처럼 한국에서 주로 쓰는 파일 형식도 있습니다. 에이전트가 이런 일을 하려면 누군가 "이 질문에는 이 API를 이렇게 불러라"를 정리해 두어야 합니다.

## k-skill이란?

k-skill은 그 정리를 스킬 127개로 묶어 둔 오픈소스입니다. 스킬은 에이전트에게 "이런 요청이 오면 이 순서로 이 명령을 써라"를 알려 주는 설명서입니다. 에이전트는 질문에 맞는 스킬을 골라 읽고, 적힌 대로 API를 부르거나 스크립트를 실행한 뒤 결과를 정리해 줍니다.

NomaDamas가 만들어 2026년 3월에 공개했습니다. Claude Code, Codex, OpenCode, OpenClaw(ClawHub)를 지원하고, Manus에서도 가져다 쓸 수 있습니다. 라이선스는 MIT이고, 프록시 서버와 그 모니터링 코드만 AGPL-3.0입니다.

## Claude Code에 설치하기

README가 안내하는 설치 명령은 두 줄입니다. Claude Code 입력창에 차례로 넣으면 됩니다.

```text
/plugin marketplace add NomaDamas/k-skill
/plugin install k-skill@k-skill
```

설치 범위를 직접 고르려면 `/plugin`을 입력하고 Discover 탭에서 k-skill을 검색해 Enter를 누르면 됩니다. 설치 방법이 세 가지로 나옵니다.

![Claude Code의 /plugin 화면. Plugin details 아래에 k-skill, from k-skill, 한국인을 위한 90+ Agent Skill 번들이라는 설명이 있고, 90+ Agent Skill에 실제 스킬은 127개라는 주황 라벨이 붙어 있다. 아래 설치 방법 세 가지 중 Install for you, in this repo only (local scope)가 선택되어 있고 이 폴더에서만 켜기라는 초록 라벨이 붙어 있다](@/assets/images/k-skill-intro/01-plugin-install.png)
*user scope는 나에게 모든 폴더에서, project scope는 이 저장소를 함께 쓰는 모든 사람에게, local scope는 나에게만 이 폴더에서 켜집니다. 2026-09-29 캡처, Claude Code 2.1.284.*

이 글에서는 시연용 폴더에서만 켜지도록 local scope를 골랐습니다. 켜짐 설정은 그 폴더의 `.claude/settings.local.json`에만 기록됩니다. 설치가 끝나면 "Installed k-skill. Plugin is now active."가 뜨고, Claude Code를 다시 시작하지 않아도 바로 쓸 수 있습니다. 터미널에서는 `claude plugin install k-skill@k-skill --scope local`처럼 `--scope` 옵션으로 범위를 고를 수 있습니다.

Claude Code가 아닌 에이전트는 README대로 아래 명령으로 설치합니다. `-g`를 붙이면 프로젝트 폴더가 아니라 사용자 전역 스킬 폴더에 들어갑니다.

```text
npx --yes skills add NomaDamas/k-skill --all -g
```

필요한 스킬만 설치하려면 `--all` 대신 `--skill <스킬 이름>`을 붙이면 됩니다.

## 써 보기: 퇴근길 질문 하나

k-skill을 켠 폴더에서 Claude Code를 열고, 스킬 이름은 말하지 않고 평소 말로 물었습니다.

```text wrap
지금 강남역에서 퇴근하려고 해. 2호선 열차가 언제 오는지랑 강남역 주변이 얼마나 붐비는지 알려 줘.
```

### 1. 스킬을 고르고 명령마다 허락을 구합니다

Claude Code는 질문을 보고 지하철 도착 정보 스킬(`seoul-subway-arrival`)과 서울 혼잡도 스킬(`seoul-density`)을 불러왔습니다. 그다음 스킬의 자세한 지침을 받아 오는 명령을 실행해도 되는지 물었습니다.

![Claude Code 화면. 맨 위에 강남역 퇴근길 질문이 있고, 그 아래 Skill(k-skill:seoul-subway-arrival)과 Skill(k-skill:seoul-density)가 Successfully loaded skill로 나온 부분에 질문에 맞는 스킬 두 개를 스스로 고름이라는 초록 라벨이 붙어 있다. 아래 Bash command 권한 확인 창에는 bunx @nomadamas/k-skill@0 instruct seoul-subway-arrival 명령과 지하철 도착 스킬 지침 가져오기라는 설명에 초록 라벨이, 1. Yes에 읽어 보고 1번(Yes)이라는 라벨이 붙어 있다](@/assets/images/k-skill-intro/02-ask-permission.png)
*스킬 두 개를 불러온 뒤 첫 명령의 허락을 구하는 화면입니다. 시연 컴퓨터는 `npx` 대신 `bunx`를 쓰도록 설정해 두어 `bunx`로 실행했습니다. 2026-09-29 캡처.*

k-skill의 스킬 파일은 짧은 안내문입니다. 에이전트는 스킬을 부르면 아래 명령을 실행합니다.

```text
npx -y @nomadamas/k-skill@0 instruct <스킬 이름>
```

그러면 CLI가 실행 환경에 맞게 조립한 실제 지침을 내려 줍니다. 그래서 스킬 파일을 다시 설치하지 않아도 늘 최신 지침을 받습니다.

답이 나올 때까지 명령 네 개를 허락했습니다. 두 스킬의 지침 받기, 지하철 도착 정보 조회, 혼잡도 조회입니다. 도착 정보는 이런 명령으로 가져왔습니다.

![Claude Code의 Bash command 권한 확인 창. curl로 k-skill-proxy.nomadamas.org의 /v1/seoul-subway/arrival에 stationName=강남을 보내는 명령에 k-skill 프록시로 강남역 도착 정보 조회라는 초록 라벨이 붙어 있고, 아래 1. Yes에 1번(Yes) 라벨이 붙어 있다](@/assets/images/k-skill-intro/03-proxy-permission.png)
*`k-skill-proxy.nomadamas.org`에 역 이름만 보내 서울 열린데이터 광장의 실시간 도착 정보를 받습니다. 제 인증키는 쓰지 않았습니다.*

### 2. 출처와 기준 시각이 붙은 답

![Claude Code의 답. 위에서부터 강남역 퇴근길 질문, 스킬 두 개를 불러온 부분, Ran 4 shell commands, 20:35 기준으로 강남역 2호선은 열차가 자주 오고 역 주변은 붐비지 않는 편이라는 첫 문장이 있다. 가운데 표에는 외선(역삼, 선릉, 잠실 방면) 다음 열차 약 1분 20초 후, 그다음 약 4분 30초 후, 내선(교대, 사당, 신도림 방면) 다음 열차 약 2분 30초 후, 그다음 약 7분 후가 방향별 다음 열차라는 초록 라벨과 함께 있다. 아래에는 혼잡도 보통, 추정 인구 54,000~56,000명에 초록 라벨, 기준 시각이 20:05라 약 30분 전 상황이라는 한계 문장에 주황 라벨, 서울 열린데이터 광장의 실시간 지하철 도착정보와 서울 실시간 도시데이터를 k-skill-proxy로 조회했다는 출처 문장에 초록 라벨이 붙어 있다](@/assets/images/k-skill-intro/04-commute-answer.png)
*권한 확인 창은 빼고 질문과 답만 이어 붙였습니다. 2026-09-29 20:35 캡처, Claude Code 2.1.284(Sonnet 5.5).*

답이 나오기까지 24초가 걸렸습니다(화면 표시 기준). 답에는 이런 내용이 들어 있었습니다.

1. 방향별로 다음 열차와 그다음 열차가 몇 분 뒤에 오는지, 지금 어느 역을 지나는지 나옵니다. API가 열차 위치를 받은 시각(20:34:41)도 적혀 있습니다.
2. 강남역 주변 혼잡도는 "보통", 추정 인구는 54,000~56,000명이었습니다.
3. 혼잡도 값이 20:05 기준이라 30분쯤 전 상황이라는 점을 에이전트가 먼저 밝혔습니다.
4. 끝에 출처(서울 열린데이터 광장의 실시간 지하철 도착정보, 서울 실시간 도시데이터)가 붙습니다.

외선과 내선 표기도 노선 순서와 맞춰 봤습니다. 역삼, 잠실 방면으로 가는 외선 열차는 교대와 방배 쪽에서, 교대, 신도림 방면으로 가는 내선 열차는 선릉과 잠실새내 쪽에서 오고 있었습니다. 방향과 위치가 서로 맞습니다.

## 인증키 없이 되는 이유, k-skill 프록시

스킬 127개 가운데 60개는 지침에 k-skill 프록시가 나옵니다(2026-09-29 저장소 기준). 공공 API의 인증키는 NomaDamas가 운영하는 프록시 서버에만 두고, 사용자는 프록시 주소로 조회 조건만 보냅니다. 그래서 공공데이터포털이나 서울 열린데이터 광장에서 키를 따로 받지 않아도 됩니다. 기여 가이드에 따르면 프록시는 무료 API만 다룹니다.

- **직접 운영하려면**: 프록시 코드도 저장소에 있습니다. `KSKILL_PROXY_BASE_URL`에 내 프록시 주소를 적으면 그쪽으로 요청합니다.
- **개인정보**: 프록시로 가는 요청의 처리 기준은 [k-skill-proxy 개인정보 처리방침](https://k-skill-proxy.nomadamas.org/privacy)에 있습니다.
- **키나 로그인이 필요한 스킬도 있습니다**: 토스증권은 본인 계정의 공식 API 인증을, 팝빌은 본인 키를, 잡코리아와 사람인 인재 검색은 기업회원 로그인을 씁니다. 필요한 값은 `k-skill-setup` 스킬이 확인하고 안내합니다.

## 쓰기 전에 알아둘 점

### 원천 기관 서버가 멈추면 스킬도 멈춥니다

같은 날 "올해 10월에 쉬는 날 알려 줘. 대체공휴일도 있으면 같이."라고도 물었습니다. Claude Code는 공휴일 스킬(`korean-holiday-calendar`)을 골랐지만, 프록시가 두 번 모두 `HTTP 500 proxy_error (fetch failed)`를 돌려줬습니다.

같은 시각 제 컴퓨터에서도 공공데이터포털(data.go.kr) 접속이 시간 초과됐고, 공공데이터포털을 거치는 미세먼지 조회도 HTTP 502를 받았습니다. 서울 열린데이터 광장을 쓰는 지하철 도착 정보는 같은 시각에 정상 응답했습니다. 프록시가 원천 기관 서버에서 값을 받아 오지 못한 경우입니다.

![Claude Code의 답. 10월 쉬는 날 질문 아래 Skill(k-skill:korean-holiday-calendar)에 공휴일 스킬을 고름이라는 초록 라벨이 있고, 공휴일 조회 API(k-skill-proxy)가 두 번 모두 500 proxy_error (fetch failed)로 실패해서 API로 확인하지 못했다는 문장에 API 실패를 먼저 밝힘이라는 초록 라벨이 있다. 가운데 표에는 10월 3일(토) 개천절, 10월 5일(월) 개천절 대체공휴일, 10월 9일(금) 한글날이 있고, 아래 2026년 추석 대체공휴일은 9월 28일(월)이라는 줄에 틀림: 2026년 추석은 대체공휴일 없음이라는 주황 라벨이 붙어 있다](@/assets/images/k-skill-intro/05-holiday-fallback.png)
*API 실패를 먼저 밝히고, 나머지는 모델이 알고 있는 규정으로 채운 답입니다. 2026-09-29 20:31 캡처.*

에이전트는 API로 확인하지 못했다는 사실을 먼저 밝히고, 알고 있는 공휴일 규정으로 답을 채웠습니다. 10월 3일(토) 개천절, 5일(월) 개천절 대체공휴일, 9일(금) 한글날은 맞았습니다. 하지만 "2026년 추석 대체공휴일은 9월 28일(월)"이라는 줄은 틀렸습니다.

우주항공청의 [2026년 월력요항](https://www.kasa.go.kr/bbs/BBSMSTR_000000000010/view.do?nttId=B000000001860Pe2zT3)에 따르면 올해 추석 공휴일은 9월 24일(목)부터 26일(토)까지 사흘입니다. 일요일인 27일까지 쉬고, 28일(월)은 평일입니다. 설과 추석은 일요일이나 다른 공휴일과 겹칠 때만 대체공휴일이 생기는데, 올해 추석 공휴일은 토요일과만 겹쳤습니다.

> [!WARNING]
> **"확인하지 못했다"는 말 뒤의 내용은 모델의 기억입니다.** 스킬이 원천 데이터를 받아 왔는지는 답에 붙은 출처와 기준 시각으로 확인할 수 있습니다. 날짜나 금액처럼 정확해야 하는 값에 출처가 없다면 공식 자료로 한 번 더 확인하세요.

### 전체 설치는 켠 곳의 모든 세션에 토큰을 더합니다

Claude Code는 설치된 스킬의 이름과 설명을 세션마다 미리 읽어 두고, 스킬을 쓸 때 본문을 엽니다. 스킬이 127개라 이 기본 비용이 작지 않습니다. `claude plugin details`로 확인한 값입니다.

```text
k-skill 1.0.0
Component inventory
  Skills (127)  animal-pharmacy-search, assembly-bill-vote-search, ...

Projected token cost
  Always-on:   ~13,993 tok   added to every session
```

*스킬 목록은 줄였습니다. 2026-09-29, Claude Code 2.1.284.*

k-skill을 켠 곳에서는 새 세션마다 약 1만 4천 토큰이 먼저 쓰입니다. 스킬 하나를 실제로 쓰면 그 스킬 본문으로 480~870토큰이 더해집니다. 부담을 줄이는 방법은 세 가지입니다.

1. **필요한 폴더에서만 켜기**: 이 글처럼 local scope로 설치합니다.
2. **필요한 스킬만 설치하기**: `npx --yes skills add NomaDamas/k-skill --skill <스킬 이름> -g`로 골라 설치할 수 있습니다.
3. **안 쓰는 스킬 정리하기**: `k-skill-cleaner` 스킬이 에이전트별로 스킬이 불린 횟수를 모아 지울 후보를 추천합니다.

### `update` 명령은 모든 에이전트에 전체 스킬을 설치합니다

스킬 지침에는 "k-skill CLI 도구를 쓰기 전에 `npx -y @nomadamas/k-skill@0 update`를 먼저 실행하라"는 규칙이 들어 있습니다. 기여 가이드에 따르면 이 명령은 CLI를 최신으로 올리면서 [앞에서 본 전체 설치 명령](#claude-code에-설치하기)도 함께 실행합니다. 허락하면 127개 전체가 `~/.agents/skills`를 비롯한 모든 코딩 에이전트의 전역 스킬 폴더에 들어갑니다.

플러그인으로 한 폴더에서만 쓰려는 경우라면 이 명령은 허락하지 않아도 됩니다. 설치 상태만 확인하려면 `update --check`를 쓰면 됩니다. 매번 거절하기 번거롭다면 그 폴더의 `.claude/settings.local.json`에 막는 규칙을 적어 둘 수 있습니다.

```json
{
  "permissions": {
    "deny": [
      "Bash(npx -y @nomadamas/k-skill@0 update:*)"
    ]
  }
}
```

시연 컴퓨터는 `npx` 대신 `bunx`를 쓰기 때문에 같은 규칙을 `bunx`로도 적어 두었습니다. 앞의 두 질문에서 에이전트는 `update`를 시도하지 않았습니다. 규칙이 동작하는지 보려고 일부러 업데이트를 부탁했더니, 명령은 거부됐고 에이전트는 우회하지 않고 멈췄습니다.

![Claude Code의 답. 업데이트 명령은 실행되지 않았고 권한 설정에서 bunx @nomadamas/k-skill@0 update가 거부됐다는 첫 문장에 차단 규칙에 걸려 실행되지 않음이라는 초록 라벨이 있다. update가 CLI를 갱신하고 내부에서 npx --yes skills add NomaDamas/k-skill --all -g로 ~/.agents/skills를 포함한 전역 스킬 설치를 덮어쓴다는 설명에 주황 라벨이, 변경 없이 상태만 보려면 update --check를 쓰면 된다는 문장에 초록 라벨이 붙어 있다](@/assets/images/k-skill-intro/06-update-denied.png)
*차단된 뒤 에이전트가 남긴 답입니다. 2026-09-29 20:46 캡처.*

시연을 마친 뒤 `~/.agents/skills`, `~/.claude/skills`, `~/.codex/skills`를 포함한 전역 스킬 폴더 여섯 곳을 확인했고, k-skill 스킬은 하나도 설치되지 않았습니다.

### 공개 웹 화면을 읽는 스킬은 사이트가 바뀌면 달라집니다

API가 아니라 공개 웹 화면을 읽는 스킬도 있습니다. 사이트 구조나 정책이 바뀌면 동작이 달라질 수 있습니다. 예를 들어 다이소 스킬은 2026-05-05부터 다이소몰 보안 정책으로 매장별 재고 수량이 막혀 픽업 가능 여부만 확인합니다. README는 공개정보 조회를 개인적, 비조직적 용도로만 쓰고 대량 수집이나 접근 통제 회피는 하지 말라고 적고 있습니다.

## 자주 묻는 질문

> [!faq]- 개발을 몰라도 쓸 수 있나요?
> 네. Claude Code 같은 에이전트에 설치한 뒤 평소 말로 부탁하면 됩니다. 에이전트가 명령을 실행해도 되는지 물으면 명령과 설명을 읽어 보고 허락하면 됩니다.

> [!faq]- 무료인가요?
> k-skill은 오픈소스(MIT)이고, 프록시를 거치는 스킬은 인증키 없이 쓸 수 있습니다. 에이전트가 쓰는 AI 모델의 요금은 각 서비스의 요금제를 따릅니다.

> [!faq]- Claude Code 말고 다른 에이전트에서도 되나요?
> 네. README는 Codex, OpenCode, OpenClaw(ClawHub)를 지원한다고 적고 있고, Manus에서 가져오는 방법도 문서로 있습니다. Claude Code가 아닌 에이전트는 `npx --yes skills add NomaDamas/k-skill`로 설치합니다.

> [!faq]- 내가 보낸 조회 조건은 어디로 가나요?
> 프록시를 거치는 스킬은 조회에 필요한 값(예: 역 이름)이 k-skill 프록시 서버를 거쳐 원천 기관 API로 갑니다. 처리 기준은 [k-skill-proxy 개인정보 처리방침](https://k-skill-proxy.nomadamas.org/privacy)에 있습니다. 대화 내용은 쓰는 에이전트의 모델 제공자에게도 전달됩니다.

> [!faq]- 예매나 결제도 대신 해 주나요?
> 고속버스, 시외버스, 자연휴양림처럼 예매를 돕는 스킬이 있습니다. 결제, 메시지 발송, 최종 제출, 취소는 실행 직전에 사용자 승인을 받도록 모든 스킬에 규칙이 들어 있습니다. KTX 스킬처럼 조회만 하는 스킬도 있습니다.
