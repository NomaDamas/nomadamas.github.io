AI에게 일을 맡기다 보면 같은 설명을 자꾸 덧붙이게 됩니다. 주간 보고를 부탁할 때는 "팀장님께 메신저로 보낼 거라 짧게", 회의록을 맡길 때는 "정해진 것과 할 일을 따로", 카드뉴스 문구를 맡길 때는 "우리 계정 말투로"를 붙입니다. AI는 보고서나 회의록을 쓰는 법은 알아도 우리 팀이 일하는 방식은 모르기 때문입니다.

새로 들어온 직원도 처음에는 그렇습니다. 일을 잘하는 사람이라도 팀의 보고 형식과 문서 규칙은 모릅니다. 그래서 회사는 온보딩 문서를 건넵니다. 한 번 읽으면 묻지 않아도 그 방식대로 일할 수 있습니다.

**AI에게도 온보딩 문서를 한 번 건네 둘 수는 없을까요?** Claude Code(클로드 코드)에서는 그런 문서를 스킬(Skill)이라고 부릅니다. 이 글은 Claude Code에 보고, 정리, 문서 작업을 맡기는 직장인을 위해 썼습니다. Claude Code 스킬이 무엇인지, 스킬이 있을 때와 없을 때 결과가 어떻게 다른지, 남이 만든 스킬은 어떻게 가져다 쓰는지, 내 첫 스킬은 어떻게 만드는지 차례로 보여 드립니다.

*스킬을 만들어 둔 폴더에서 주간 보고를 한 줄로 맡긴 화면입니다(2026-10-13, Claude Code 2.1.296, Opus 5.5). 영상 17초, 소리 없음. 답을 기다리는 구간은 2배 빠르게 돌렸습니다.*

> **요약**
>
> 1. Claude Code 스킬은 우리 팀이 일하는 방식을 적어 둔 `SKILL.md` 파일입니다. 한 번 적어 두면 부탁할 때마다 덧붙이던 설명 없이 그 방식대로 일합니다. 평소에는 이름과 짧은 설명만 읽어 두고 부탁이 설명과 맞을 때 본문을 읽습니다.
> 2. 같은 "주간 보고 써 줘"에 스킬이 없을 때는 `#`, `**` 같은 서식 기호가 든 21줄짜리 보고서를 파일로 저장하고 대화창에도 같은 내용을 썼습니다. 스킬을 만든 뒤 다음 주 메모로 맡기자 결정 요청을 맨 위에 둔 8줄짜리 메신저용 보고를 대화창에 썼습니다.
> 3. 남이 정리해 둔 방식도 가져다 쓸 수 있습니다. NomaDamas의 [k-skill](https://github.com/NomaDamas/k-skill)로 한글(HWP) 보도자료를 표 모양 그대로 읽고, KTX 시간표를 찾고, 맞춤법을 검사했습니다.
> 4. 첫 스킬은 매번 고쳐 주던 점을 한국어로 적어 "스킬로 만들어 줘"라고 부탁하면 됩니다. 만들기 전에 내용을 보고 싶다면 Shift+Tab을 눌러 파일을 쓰기 전에 허락을 묻는 Manual 모드로 바꾼 뒤 부탁하면 됩니다.

## 목차

## Claude Code 스킬이란?

스킬은 AI 에이전트(Claude Code처럼 파일을 읽고 명령을 실행하며 일하는 AI)에게 특정한 일을 하는 방법을 알려 주는 문서입니다. 폴더 하나에 `SKILL.md` 파일을 둡니다. 맨 위에는 스킬의 이름과 언제 쓰는지를, 그 아래에는 일하는 방법을 평범한 글로 적습니다. 일에 필요한 참고 문서나 프로그램(스크립트)을 같은 폴더에 넣어 둘 수도 있습니다.

![Anthropic이 공개한 SKILL.md 예시. pdf 스킬 파일의 맨 위 머리말에 이름(name: pdf)과 설명(description)이 있고, 그 아래 본문에 개요와 빠른 시작 안내가 있다](@/assets/images/claude-code-skills/01-skill-anatomy.webp)
*스킬 파일의 구조입니다. 위쪽 YAML Frontmatter 칸에 이름과 설명을, 아래쪽 Markdown 칸에 지침을 적습니다. 출처: Anthropic, [Equipping agents for the real world with Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)*

이 형식을 만든 Anthropic은 스킬을 이렇게 설명합니다. "에이전트에게 스킬을 만들어 주는 일은 새 직원을 위한 온보딩 가이드를 준비하는 일과 같습니다." 새 직원이 첫날 회사 규정을 모두 외우지 않듯이 Claude Code도 스킬을 한꺼번에 읽지 않습니다.

1. Claude Code를 켜면 스킬마다 이름과 설명만 읽어 둡니다.
2. 부탁이 들어오면 설명이 맞는 스킬을 골라 본문을 읽고 그대로 일합니다.
3. 본문이 가리키는 참고 문서나 프로그램은 필요할 때만 엽니다.

AI가 한 대화에서 읽어 둘 수 있는 양에는 한도가 있습니다. 스킬은 평소에 설명 몇 줄만큼만 이 한도를 쓰므로 여러 개 넣어 두어도 부담이 적습니다. 부탁할 때 스킬 이름을 말하지 않아도 됩니다. 입력창에서 `/스킬이름`으로 직접 부를 수도 있습니다.

스킬은 넣어 두는 곳에 따라 쓰이는 범위가 달라집니다.

| 스킬 폴더를 넣는 곳 | 쓰이는 범위 |
|---|---|
| 작업 폴더 안의 `.claude/skills/` | 그 폴더에서 연 Claude Code |
| 내 홈 폴더의 `~/.claude/skills/` | 이 컴퓨터의 모든 폴더 |

`~`는 내 홈 폴더를 뜻합니다. Mac의 Finder에서는 이름이 점(.)으로 시작하는 폴더가 숨겨져 있어서 Command+Shift+.(마침표)를 눌러야 보입니다.

스킬 형식은 에이전트 스킬([Agent Skills](https://agentskills.io))이라는 공개 표준이기도 해서 Codex, Gemini CLI, Cursor, GitHub Copilot 같은 다른 에이전트도 같은 `SKILL.md`를 읽습니다.

## 스킬이 있으면 결과가 얼마나 달라질까?

시연 폴더에는 가상의 팀원이 한 주 동안 적은 업무 메모 하나만 두었습니다. 고객 세미나를 준비하는 한 주입니다.

![시연 폴더의 업무 메모. 10월 12일부터 16일까지 세미나 장소 후보 비교, A센터 견적 요청, 신청 페이지 초안, 경품 아이디어, 뉴스레터 오픈율, 대관비 예산 승인 필요, 다음 주 연사 섭외가 적혀 있다. 아래에 '이번 주 업무 메모로 주간 보고 써 줘'라는 부탁과 '이 폴더에 스킬 없음' 표시가 있다](@/assets/images/claude-code-skills/02-memo-week1.png)
*가상으로 만든 업무 메모입니다.*

이 팀은 주간 보고를 팀장님께 메신저로 보내고 팀장님이 결정해 주셔야 할 일을 맨 위에 둡니다. 부탁에는 이 방식을 적지 않고 Claude Code에 "이번 주 업무 메모로 주간 보고 써 줘"라고만 했습니다.

![스킬 없이 맡긴 결과. Claude Code가 주간보고-1012-1016.md 파일에 21줄짜리 보고서를 저장했고, 파일 앞부분에는 제목 기호와 굵은 글씨 기호가 그대로 있다. 이어서 대화창에도 같은 보고를 제목과 항목으로 나눠 썼는데, 32% 앞뒤에 굵은 글씨 기호가 남은 곳이 있고 결정 요청은 '요청 사항'으로 중간에 있다. 다음 주 계획에는 메모에 없던 할 일이 들어갔고, 끝에는 메모에 없던 내용을 넣었다고 밝혔다. 빨간 표시 네 개는 파일로 저장한 점, 파일과 대화창 글에 남은 서식 기호, 중간에 있는 결정 요청을 가리키고, 주황 표시는 메모에 없던 할 일을, 초록 표시 두 개는 대화창에도 같은 보고를 쓴 점과 넣은 내용을 스스로 밝힌 점을 가리킨다](@/assets/images/claude-code-skills/03-noskill-report.png)
*스킬이 없을 때(2026-10-13, Claude Code 2.1.296, Opus 5.5). 빨간 표시는 팀 방식과 다른 곳, 주황 표시는 메모에 없던 내용, 초록 표시는 잘한 점입니다.*

보고서로는 잘 쓴 편입니다. 메모 내용을 빠뜨리지 않았고 메모에 없던 할 일을 넣었다는 사실도 스스로 밝혔습니다. 다만 이 팀이 보고하는 방식은 아닙니다. 보고는 21줄짜리 파일(빈 줄 포함)로 저장했습니다. 파일에 든 `#`과 `**` 같은 서식 기호는 메신저에 붙이면 글자 그대로 보입니다. 대화창에도 같은 보고를 썼지만 제목과 항목으로 나뉜 긴 보고서 형식이었고 32% 앞뒤처럼 `**` 기호가 남은 곳도 있었습니다. 팀장님이 결정해 주셔야 할 일은 보고서 중간의 '요청 사항'에 들어 있습니다.

스킬이 없으면 이 차이를 부탁할 때마다 설명해야 합니다. 파일 말고 대화창에, 결정할 일은 맨 위에, 한 줄씩, 열 줄 안으로. 이 설명을 한 번 적어 둔 것이 스킬입니다. 이 대화에 이어 weekly-report 스킬을 만들었습니다. 만드는 과정은 [아래](#내-첫-스킬은-어떻게-만들까)에서 보여 드립니다.

만든 스킬에는 이번 주 메모로 쓴 보고가 예시로 들어갔습니다. 예시를 그대로 옮기는 것과 구분하려고 가상으로 만든 다음 주 메모로 같은 부탁을 했습니다.

![다음 주 업무 메모. 10월 19일부터 23일까지 대관비 예산 승인과 A센터 예약, 견적 회신, 신청 페이지 검토와 수정, 연사 섭외, 사전 설문 제안, 경품 후보, 신청 페이지 공개 시점 결정 필요, 다음 주 할 일이 적혀 있다. 아래에 같은 부탁과 'weekly-report 스킬 있음' 표시가 있다](@/assets/images/claude-code-skills/04-memo-week2.png)
*가상으로 만든 다음 주 업무 메모입니다.*

![스킬이 있을 때의 결과. Claude Code가 weekly-report 스킬을 불러오고, 대화창에 8줄 보고를 썼다. 첫 줄은 '결정 부탁드립니다'로 시작해 경품 선택과 신청 페이지를 여는 시점 두 가지를 묻고, 그 아래에 끝낸 일, 진행 중, 다음 주를 한 줄씩 적었다. 초록 표시로 '스킬을 스스로 불러옴', '결정 요청이 맨 위', '정하지 않은 일은 (제안)', '마감, 모르면 마감 미정'이 붙어 있다](@/assets/images/claude-code-skills/05-skill-report.png)
*스킬이 있을 때(2026-10-13, Claude Code 2.1.296, Opus 5.5). 글 머리 영상과 같은 실행입니다.*

부탁에 스킬 이름을 넣지 않았는데도 Claude Code가 weekly-report 스킬을 골라 읽었습니다. 보고는 파일 없이 대화창에 썼고 서식 기호도 없습니다. 첫 줄에는 결정해 주셔야 할 일 두 가지에 번호를 붙여 모았습니다. 회의에서 나온 사전 설문 아이디어에는 (제안)을, 마감일이 없는 할 일에는 (마감 미정)을 붙였습니다. 모두 8줄이고 메모와 한 줄씩 맞춰 봐도 지어낸 내용은 없습니다.

부탁할 때마다 이 설명을 붙여서 같은 방식을 요청할 수도 있습니다. 스킬은 그 설명을 붙이지 않아도 되게 해 줍니다. 스킬이 든 폴더를 팀과 나눠 쓰면 팀원에게도 같은 방식이 적용됩니다.

## k-skill로 한국 업무도 맡길 수 있을까?

![케이-스킬이라는 제목과 "한국인의, 한국인에 의한, 한국인을 위한 스킬 모음집"이라는 부제 뒤로 한국 스포츠 선수, 가수, 만화 캐릭터 사진을 모아 붙인 k-skill 대표 이미지](@/assets/images/k-skill-intro/00-k-skill-thumbnail.png)
*[k-skill 저장소](https://github.com/NomaDamas/k-skill) README의 대표 이미지입니다.*

**GitHub: [github.com/NomaDamas/k-skill](https://github.com/NomaDamas/k-skill)**

스킬은 직접 만들 수도 있고 남이 만든 것을 가져다 쓸 수도 있습니다. k-skill은 저희 NomaDamas가 만든 오픈소스(누구나 코드를 보고 무료로 쓸 수 있게 공개한 프로그램) 스킬 모음입니다. 한글(HWP) 문서 읽기, KTX 시간표, 맞춤법 검사처럼 한국에서 일하고 생활할 때 필요한 스킬 131개가 들어 있습니다.

k-skill 저장소(코드와 문서를 올려 두는 GitHub의 프로젝트 공간)는 star를 7,907개 받았습니다. star는 개발자가 마음에 드는 저장소에 누르는 추천 표시입니다. 올해 GitHub에 새로 만들어진 공개 저장소 7,800만여 개(복사본인 포크 제외) 가운데 383번째로 많습니다(2026년 10월 13일, GitHub 검색으로 센 값). 써 보고 도움이 됐다면 GitHub에 로그인한 뒤 저장소 오른쪽 위의 Star 버튼을 눌러 주세요.

이번에는 131개를 모두 넣지 않고 쓸 스킬 세 개만 시연 폴더에 설치했습니다. 스킬을 쓸 폴더에서 Claude Code를 열고 입력창에 `!`를 친 뒤 아래 명령을 붙여 넣으면 됩니다. `!`로 시작한 줄은 AI에게 부탁하지 않고 바로 명령으로 실행됩니다. 결과가 나오면 Claude Code가 그 결과를 읽고 답합니다. 터미널(명령을 입력하는 창)에서 그 폴더로 이동해 실행해도 됩니다.

```bash
npx --yes skills add NomaDamas/k-skill --skill hwp railway-timetable korean-spell-check -a claude-code -y
```

![터미널에서 skills 명령으로 k-skill의 스킬 131개 가운데 hwp, korean-spell-check, railway-timetable 세 개만 골라 설치한 화면. 초록 표시로 '-g 없이: 이 폴더에만 설치', '131개 중 3개만', './.claude/skills/ 에 들어감', 주황 표시로 '쓰기 전에 내용을 확인하라는 경고'가 붙어 있다](@/assets/images/claude-code-skills/06-kskill-install.png)
*2026-10-13, skills 1.7.2. 마지막 줄은 스킬 안의 지시와 프로그램이 Claude Code와 같은 권한으로 내 컴퓨터에서 실행되니 쓰기 전에 내용을 보라는 안내입니다.*

`-g`를 붙이지 않아서 스킬은 이 폴더의 `.claude/skills/`에만 들어갔습니다. `-g`를 붙이면 이 컴퓨터의 모든 폴더에서 쓰입니다.

설치에는 Node.js(자바스크립트 프로그램을 실행하는 도구)가 필요합니다. 스킬마다 더 필요한 프로그램도 있습니다. 이번에 쓴 KTX 시간표 스킬은 uv(파이썬 프로그램을 실행하는 도구)가, 맞춤법 스킬은 파이썬(python3)이 있어야 실행됩니다. 입력창에서 `!`로 설치했는데 그 폴더에 `.claude/skills/`가 처음 생겼다면, 이어서 `/reload-skills`를 입력해야 새 스킬을 불러옵니다.

> [!WARNING]
> k-skill의 스킬은 일을 시작하기 전에 아래 갱신 명령을 실행하라고 안내합니다.
>
> ```bash
> npx -y @nomadamas/k-skill@0 update
> ```
>
> 이 명령은 k-skill에 든 스킬 전부를 모든 폴더에서 쓰이게 설치합니다. 위 표의 `~/.claude/skills/` 같은 홈 폴더 쪽 스킬 폴더와 `~/.agents/skills/`에 들어갑니다. 설치에 쓴 skills 도구가 아는 에이전트라면 이 컴퓨터에 깔려 있지 않아도 그 에이전트의 스킬 폴더에 설치합니다.
>
> 이번 시연에서는 이 폴더의 권한 설정으로 이 명령을 막아 두었고 막힌 뒤에도 Claude Code는 갱신 없이 일을 마쳤습니다. 이 폴더에서만 쓰려면 [k-skill 소개 글](/posts/k-skill-intro/#update-명령은-모든-에이전트에-전체-스킬을-설치합니다)의 설정으로 이 명령을 막아 두면 됩니다. 기본값인 auto 모드에서는 검사 모델이 대신 판단해서 실행해도 되는지 묻지 않을 수 있습니다. 실행 전에 직접 확인하려면 Manual 모드로 바꿔 두면 됩니다.

### 한글(HWP) 보도자료 읽기

한글(HWP) 파일은 일반 텍스트 파일과 구조가 달라서 읽으려면 따로 프로그램이 필요합니다. 대전시가 낸 [수소차 구매 보조금 보도자료](https://www.daejeon.go.kr/drh/board/boardNormalView.do?boardId=normal_0189&menuSeq=1632&ntatcSeq=1505811133)(공공누리 제1유형)를 스킬이 없는 폴더와 k-skill을 설치한 폴더에 하나씩 넣고 "대전시-수소차-보조금-보도자료.hwp 핵심만 정리해 줘"라고 부탁했습니다.

### 맞춤법 검사

회의 결과를 팀에 알리는 짧은 초안을 일부러 틀리게 써 두고 "회의결과-공유-초안.txt 맞춤법 검사해 줘"라고 부탁했습니다.

```text wrap
팀원 여러분, 어제 회의 결과 공유드립니다.

몇일 전에 말씀드린 세미나 일정이 바꼈습니다. 장소 예약이 안되서 날짜를 일주일 미루기로 했어요.
금새 다시 공지 드릴께요. 각자 역활은 그대로 진행하시면 됩니다.
혹시 일정이 안 맞으시는 분은 오늘 중으로 알려 주세요. 왠만하면 이번 주 안에 확정하겠습니다.
```

![맞춤법 검사를 부탁한 화면. Claude Code가 맞춤법 스킬을 고르고 바른한글 검사기로 7곳을 찾은 뒤, 교정본, 원문과 교정안과 이유를 담은 표, 바꾸지 않아도 되는 제안 두 가지를 보여 주고 파일에 반영할지 물었다](@/assets/images/claude-code-skills/11-spell.png)

korean-spell-check 스킬은 부산대학교와 나라인포테크가 만든 맞춤법 검사기 '바른한글'에 글을 보내 결과를 받습니다. '몇일'은 '며칠'로, '역활'은 '역할'로 고치는 등 7곳을 찾았습니다. 고친 글 전체를 보여 준 뒤 원문과 교정안, 이유를 표로 정리했습니다. 검사기가 권하지만 고치지 않아도 되는 표현은 따로 구분했고 파일에 반영하기 전에 반영할지 물었습니다.

검사할 글은 이 검사기의 서버로 전송됩니다. 스킬 지침도 민감한 정보가 많은 글처럼 바깥 웹 서비스에 보내면 안 되는 글에는 이 스킬을 쓰지 말라고 적어 두었습니다. 검사기 페이지에도 비상업적 용도로만 쓸 수 있고 개인이나 학생만 무료라는 안내가 있습니다. 회사 업무에 쓰려면 이용 조건부터 확인해야 합니다.

## 내 첫 스킬은 어떻게 만들까?

스킬은 `SKILL.md`를 직접 써서 만들 수도 있지만 Claude Code에 한국어로 부탁하는 편이 쉽습니다. 앞의 weekly-report 스킬도 그렇게 만들었습니다.

<video src="/videos/claude-code-skills/create-skill.mp4" poster="/videos/claude-code-skills/create-skill.jpg" controls muted playsinline preload="metadata" width="100%" aria-label="스킬 없이 받은 주간 보고 아래에 스킬로 만들어 달라는 부탁과 규칙 여섯 줄을 입력하자, Claude Code가 SKILL.md 내용을 보여 주며 만들어도 되는지 묻고, 1번 Yes로 승인하자 .claude/skills/weekly-report/SKILL.md를 만든 뒤 내가 말하지 않은 부분을 어떻게 정했는지 알려 주는 과정"></video>

*2026-10-13, Claude Code 2.1.296, Opus 5.5, Manual 모드. 영상 32초, 소리 없음. Claude Code가 생각하고 파일을 쓰는 구간은 4배 빠르게 돌렸고 보내기 전과 권한 확인 창에서 기다린 시간은 줄였습니다.*

### 1. 매번 고쳐 주던 점을 적어 부탁합니다

스킬을 쓸 폴더에서 Claude Code를 열고 결과를 받을 때마다 고쳐 주던 점을 번호를 붙여 적으면 됩니다. 주간 보고 스킬은 스킬 없이 보고를 받은 대화에 이어서 이렇게 부탁했습니다.

```text wrap
주간 보고를 맡길 때마다 내가 고쳐 주는 게 있어. 이 폴더에서 쓰는 스킬로 만들어 줘.

1. 팀장님께 메신저로 보낸다. 파일로 만들지 말고 대화창에 바로 쓴다. #, ** 같은 기호는 메신저에서 그대로 보이니 쓰지 않는다.
2. 맨 위 한 줄에는 팀장님이 결정해 주셔야 할 일을 쓴다.
3. 그 아래는 끝낸 일, 진행 중인 일, 다음 주 할 일 순서로 항목마다 한 줄씩 쓴다.
4. 회의에서 나온 아이디어처럼 아직 정하지 않은 일은 앞에 (제안)을 붙인다.
5. 다음 주 할 일에는 마감일을 붙인다. 메모에 없으면 지어내지 말고 '마감 미정'이라고 쓴다.
6. 전체 열 줄을 넘기지 않는다.
```

줄을 바꾸려면 Shift+Enter를, 줄이 바뀌지 않는 터미널에서는 Ctrl+J를 누르면 됩니다. 규칙은 "짧게"보다 "열 줄을 넘기지 않는다"처럼 지켰는지 확인할 수 있게 쓰는 편이 좋습니다. 모르는 값을 어떻게 할지("메모에 없으면 마감 미정")도 적어 두면 AI가 지어낼 여지가 줄어듭니다.

### 2. 만들기 전에 파일 내용을 확인합니다

Claude Code 2.1.283부터는 터미널에서 시작할 때 auto 모드가 기본값입니다. auto 모드에서는 별도의 검사 모델이 사람 대신 판단해서 스킬 파일을 묻지 않고 만들 수 있습니다. 만들기 전에 내용을 직접 보고 싶다면 Shift+Tab을 한 번 눌러 화면 아래 상태 줄에 `manual mode on`이 보이게 한 뒤 부탁하면 됩니다. 이 시연도 Manual 모드에서 했습니다.

![Manual 모드의 권한 확인 창. 만들 SKILL.md의 출력 방식과 구성 규칙이 줄 번호와 함께 보이고, 아래에 'Do you want to create SKILL.md?'라는 질문과 1. Yes, 2. Yes, and allow Claude to edit files in this project's .claude folder for this session, 3. No 선택지가 있다. 초록 표시 '내가 준 규칙이 들어갔는지 확인', 주황 표시 '만들기 전에 묻는 권한 창', 초록 표시 '1. Yes로 승인'](@/assets/images/claude-code-skills/12-skill-permission.png)
*Manual 모드의 권한 확인 창입니다(2026-10-13, Claude Code 2.1.296, Opus 5.5).*

Manual 모드에서는 파일을 만들기 전에 내용을 보여 주고 만들어도 되는지 묻습니다. 내가 준 규칙이 빠짐없이 들어갔는지 읽고 1번 Yes를 고르면 만들어집니다. 2번을 고르면 이 대화가 끝날 때까지 이 폴더의 `.claude` 안 파일은 묻지 않고 고칩니다.

### 3. Claude Code가 정한 부분을 확인합니다

![스킬을 만든 뒤의 화면. 파일 위치 .claude/skills/weekly-report/SKILL.md, '다음부터 주간 보고 써 줘라고 하시거나 /weekly-report를 입력하시면 이 규칙대로 씁니다'라는 안내, 아직 실제로 실행해 보지 않았으니 새 세션에서 써 보고 확인해 달라는 말, 스킬 안에 넣은 예시 보고 7줄, '말씀하신 규칙 외에 제가 정한 부분입니다'로 시작하는 칸 구분, 열 줄 세는 법, 결정할 일이 여러 개일 때의 규칙이 보인다. 초록 표시 '스킬 파일 위치', '다음부터 주간 보고 써 줘 한 줄로', 주황 표시 '아직 써 보지 않음: 새 대화에서 확인', 'Claude Code가 정한 부분: 확인'](@/assets/images/claude-code-skills/13-skill-created.png)
*2026-10-13, Claude Code 2.1.296, Opus 5.5.*

만든 뒤에는 파일 위치와 쓰는 법을 알려 줬고 이번에는 내가 말하지 않은 부분을 어떻게 정했는지도 밝혔습니다. '끝낸 일', '진행 중', '다음 주'를 제목 줄로 두지 않고 각 줄 앞에 붙였고 열 줄은 첫 줄까지 포함해 빈 줄 없이 세기로 했습니다. 내 방식과 다르면 "구분 제목 줄을 따로 둬"처럼 말해 고칠 수 있습니다. Claude Code도 아직 써 보지 않았다며 새 대화에서 확인해 보라고 권했습니다.

이렇게 만든 49줄짜리 `SKILL.md` 전문입니다. 내 업무에 맞게 고쳐 쓰는 출발점으로 삼을 수 있습니다.

```markdown wrap
---
name: weekly-report
description: 업무 메모로 팀장님께 메신저로 보낼 주간 보고를 쓴다. "주간 보고 써 줘", "이번 주 보고 정리해 줘"처럼 주간 보고나 업무 메모 정리를 부탁받으면 사용한다.
---

# 주간 보고 작성

팀장님께 메신저로 보낼 주간 보고를 쓴다. 이 폴더의 업무 메모(예: `이번주-업무메모.md`)를 읽고, 메모가 여러 개면 날짜가 가장 최근인 것을 쓴다.

## 출력 방식

- 파일로 만들지 않는다. 대화창에 바로 쓰고, 사용자가 그대로 복사해 붙여 넣을 수 있게 한다.
- 메신저에서는 마크다운 기호가 그대로 보이므로 #, **, *, `, >, 표, 코드 블록, 글머리 기호(-)를 쓰지 않는다.
- 보고 본문 앞뒤에 덧붙이는 말은 본문과 구분되게 짧게 쓴다.

## 구성

1. 첫 줄: 팀장님이 결정해 주셔야 할 일. 여러 개면 한 줄에 ①②③으로 이어 쓴다. 없으면 "결정 요청 없음"이라고 쓴다.
2. 그 아래는 끝낸 일, 진행 중인 일, 다음 주 할 일 순서로 쓴다. 항목마다 한 줄씩 쓰고, 줄 맨 앞에 "끝낸 일:", "진행 중:", "다음 주:"를 붙여 구분한다. 줄 수를 아끼기 위해 구분용 제목 줄은 따로 두지 않는다.
3. 회의에서 나온 아이디어처럼 아직 정하지 않은 일은 내용 앞에 (제안)을 붙인다.
4. 다음 주 할 일에는 마감일을 괄호로 붙인다. 메모에 마감일이 없으면 지어내지 말고 (마감 미정)이라고 쓴다.
5. 빈 줄 없이 첫 줄까지 포함해 전체 열 줄을 넘기지 않는다. 넘치면 비슷한 항목을 한 줄로 합치고, 그래도 넘치면 덜 중요한 끝낸 일부터 줄인다.

## 내용 원칙

- 메모에 없는 사실은 쓰지 않는다. 회신이 안 온 일은 완료로, 제안은 확정으로 바꿔 쓰지 않는다.
- 숫자가 있으면 비교 대상과 함께 쓴다 (예: 오픈율 32%, 8월 28% 대비 +4%p).
- 메모가 애매해서 어느 칸에 넣을지 판단이 갈린 항목이 있으면 본문 뒤에 한 줄로 알린다.

## 예시

메모:
- 고객 세미나 장소 후보 3곳 비교 끝냄. 강남 A센터가 제일 나음 (80석, 프로젝터 있음, 역에서 5분)
- A센터에 견적 요청 메일 보냄. 회신 아직 없음
- 세미나 신청 페이지 초안 완성. 팀장님 검토 전
- 화요일 회의에서 김 대리가 참가자 경품으로 텀블러 주자고 함. 정한 건 아님
- 9월 뉴스레터 오픈율 32% (8월 28%)
- 장소 예약하려면 대관비 예산 승인 필요 (팀장님)
- 다음 주: 연사 후보 2명에게 섭외 메일 보내기

보고:

결정 부탁드립니다: ① 세미나 장소(강남 A센터) 대관비 예산 승인 ② 세미나 신청 페이지 초안 검토
끝낸 일: 세미나 장소 후보 3곳 비교, 강남 A센터로 정함 (80석, 프로젝터 있음, 역에서 5분)
끝낸 일: 세미나 신청 페이지 초안 완성
끝낸 일: 9월 뉴스레터 오픈율 32% (8월 28% 대비 +4%p)
진행 중: A센터 견적 요청 메일 발송, 회신 대기
진행 중: (제안) 참가자 경품으로 텀블러 (김 대리 제안, 미정)
다음 주: 연사 후보 2명에게 섭외 메일 발송 (마감 미정)
```

### 4. 새 대화에서 스킬을 확인합니다

![Claude Code에서 /skills를 입력한 화면. 스킬 목록에 weekly-report가 project 표시, 약 40토큰 표시와 함께 보인다. 초록 표시 '이 폴더의 스킬, 평소엔 설명 약 40토큰만'](@/assets/images/claude-code-skills/14-skills-list.png)
*2026-10-13, Claude Code 2.1.296.*

Claude Code를 새로 열고 `/skills`를 입력하면 스킬 목록에 weekly-report가 보입니다. 옆의 숫자는 스킬 이름과 설명의 길이를 어림한 값으로 약 40토큰입니다. 토큰은 AI가 글을 읽고 쓰는 단위입니다. 이제 "이번 주 업무 메모로 주간 보고 써 줘"만 보내도 [앞에서 본 보고](#스킬이-있으면-결과가-얼마나-달라질까)와 같은 형식으로 받을 수 있습니다. 처음 몇 번은 결과를 메모와 맞춰 보고 어긋난 곳은 스킬에 한 줄 더하면 됩니다.

주간 보고가 아니어도 됩니다. 결과를 받을 때마다 같은 점을 고쳐 주게 되는 일이면 스킬로 만들 만합니다.

- 회의록: 정해진 것, 할 일, 담당자를 나눠 적는 순서
- 보도자료와 공지: 회사 표기 규칙, 문장 길이, 쓰지 않는 표현
- SNS 글과 카드뉴스: 채널마다 다른 길이와 말투
- 엑셀 정리: 열 이름, 날짜 형식, 합계 내는 법

AI는 우리 팀이 일하는 방식을 모릅니다. 매번 덧붙이던 설명을 `SKILL.md`에 적어 두면 다음부터는 처음부터 그 방식대로 일합니다. 결과를 받을 때마다 고쳐 주는 점이 있다면, 그 점을 몇 줄로 적어 스킬로 만들어 보세요.

## 자주 묻는 질문

> [!faq]- 스킬을 쓰면 돈이 더 드나요?
> 스킬은 파일이라 따로 값을 내지 않습니다. Claude Code는 Pro, Max, Team, Enterprise 요금제나 Console(API) 계정, 또는 Amazon Bedrock 같은 클라우드 계정으로 쓸 수 있고 무료 요금제에는 들어 있지 않습니다. 다만 스킬 설명은 대화마다 읽히므로 그 길이만큼 토큰을 씁니다. 요금제의 사용량과 API 요금은 쓴 토큰에 따라 늘어나는데 이 글의 weekly-report 스킬은 설명이 약 40토큰이었고 본문은 쓸 때만 읽습니다. [k-skill](https://github.com/NomaDamas/k-skill)은 MIT 라이선스(회사 업무에도 무료로 쓰고 고칠 수 있는 조건)의 오픈소스입니다. 맞춤법 검사기처럼 스킬이 쓰는 바깥 서비스에는 따로 이용 조건이 있을 수 있습니다.

> [!faq]- CLAUDE.md와 무엇이 다른가요?
> CLAUDE.md는 Claude Code가 대화를 시작할 때마다 통째로 읽는 파일입니다. 스킬은 평소 이름과 설명만 읽고 본문은 그 일을 맡을 때 읽습니다. 모든 작업에서 지킬 규칙은 CLAUDE.md에, 특정한 일을 하는 방법은 스킬에 두면 됩니다.

> [!faq]- 만든 스킬을 팀원과 같이 쓸 수 있나요?
> 작업 폴더의 `.claude/skills/`에 둔 스킬은 그 폴더에서 Claude Code를 여는 사람 모두에게 적용됩니다. 팀이 같이 쓰는 GitHub 저장소에 `.claude/skills/` 폴더째 올려 두면 팀원도 같은 방식으로 맡길 수 있습니다. 나만 모든 폴더에서 쓰려면 홈 폴더의 `~/.claude/skills/`에 두면 됩니다.

> [!faq]- 스킬을 불러오지 않으면 어떻게 하나요?
> 먼저 `/skills`로 목록에 있는지 보면 됩니다. 대화 도중에 `.claude/skills` 폴더를 처음 만들었다면 `/reload-skills`를 입력하거나 Claude Code를 새로 열면 됩니다. 부탁이 스킬 설명과 많이 다르면 스킬을 고르지 않을 수 있습니다. 그럴 때는 `/weekly-report`처럼 스킬 이름을 입력해 직접 부를 수 있습니다.

> [!faq]- What is a Claude Code skill?
> A skill is a folder with a `SKILL.md` file: a name and a description at the top, then plain-language instructions for one kind of task. Claude Code keeps only the name and description in view and loads the full instructions when a request matches. In our test, the request "write this week's report" without a skill produced a 21-line Markdown report saved to a file and repeated in the chat; with the skill, the same request on the next week's notes produced an 8-line, messenger-ready report.
