# 발행한 글 공유

발행한 블로그 글을 SNS에 알리는 짧은 글을 만든다. 게시는 이 절차에 들지 않는다.

## 목차

- 시작 조건과 먼저 읽는 문서
- 플랫폼과 언어
- 순서
- 초안 파일 템플릿
- 공유 뒤 유입 확인

## 시작 조건과 먼저 읽는 문서

- 실제 페이지에 최신 수정이 올라간 것을 확인한 뒤 시작한다(`publish.md` 머지와 발행 확인 절). 고치기 전 글로 링크가 나가면 되돌릴 수 없다.
- 쓰기 전에 `recheck_values.py <작업 폴더>/recheck.tsv`를 돌린다. 공유 글의 수치는 이 조회값으로 쓴다.
- 훅 후보를 만든 뒤 글을 고쳤으면 후보를 고친 원고와 근거 표에서 다시 만든다. 고치기 전 후보에는 바로잡기 전 사실(시간, 위치, 뺀 문구)이 그대로 남는다.
- 이 저장소의 플레이북과 플랫폼 파일(`threads.md`, `x.md`), 브랜드 문서를 읽는다. 길이, 링크 위치, 이미지, 시간대, 훅 패턴은 플레이북이 정본이다.
- 블로그는 합니다체지만 SNS는 플레이북이 정한 종결을 쓴다. 블로그 문장을 그대로 옮기지 않는다.

## 플랫폼과 언어

사용자가 따로 정하지 않으면 아래 두 벌을 만든다.

| 플랫폼 | 언어 | 형식의 정본 |
|---|---|---|
| Threads | 한국어 | 이 저장소의 `threads.md` |
| X | 영어 | 이 저장소의 `x.md` |

- X 길이는 가중치로 잰다. 한글과 한자는 2, URL은 길이와 관계없이 23이다.
- 글이 한국어인데 영어로 공유하면 링크 앞에 "(in Korean)"을 붙인다.

## 순서

1. 글에서 공유할 사실 2~3개를 고른다. 근거 표(`claims.md`)에 있는 사실만 쓰고, 초안의 출처 표에는 근거 표의 원고 문장을 옮겨 적는다. 행 번호로 가리키면 근거 표를 고칠 때 번호가 밀린다.
2. 훅 후보를 2~3개 만들어 사용자가 고르게 한다.
    - 플레이북이 지금 쓸 훅 패턴을 하나로 정해 두었으면 그 기준선 안에서 소재와 문구만 바꾼다. 다른 패턴을 섞어 내면 사용자가 고른 안이 기준선을 깬다.
    - 글 속 시연 장면(특정 문서, 특정 질문)보다 독자가 품는 넓은 바람이나 질문(예: "AI가 내 컴퓨터의 데이터를 전부 읽을 수는 없을까?")으로 연다.
    - 화제가 된 다른 제품이나 사건과 견주는 훅은 그 대상의 공식 발표로 사실을 확인한다.
3. 고른 훅으로 플랫폼마다 쓴다. 플랫폼 형식에 맞춰 길이와 줄바꿈을 다시 잡는다.
4. 링크마다 UTM을 붙인다: `utm_source=<threads|x>&utm_medium=social&utm_campaign=<slug>&utm_content=<ko|en>`.
5. 이미지는 글에 실린 이미지 중 고른다. 표지(`00-cover.png`)나 내용이 한눈에 보이는 그림 1장이다.
6. 블로그 원고에서 받은 교정이 공유 글에도 적용된다. `corrections.py check <초안 파일>`을 돌려 걸린 곳을 고친다.
7. 발행 전 점검표를 채워 사용자에게 보인다. 게시는 플랫폼, 계정, 문구를 밝혀 따로 승인받는다.

사용자가 공유를 미루면 초안 파일을 만들지 않는다. 훅 후보와 초안(고른 안이 있으면 표시)을 이 글 작업을 추적하는 이슈에 코멘트로 남긴다. 대화에만 두면 다음 세션이 찾지 못한다.

## 초안 파일 템플릿

이 저장소 `README.md`에서 글의 주제 소유자와 초안 위치를 고른다. 기존 초안이 있으면 그 파일을 갱신한다. 사용자가 고른 안을 최종안으로 두고, 고르지 않은 안은 아래에 남긴다.

````markdown
---
target: <실제 글 주소>
channel: nomadamas
platforms: [threads, x]
langs: [ko, en]
hook: <고른 훅과 고른 이유 한 줄>
facts_checked: <YYYY-MM-DD>
---
````

## 공유 뒤 유입 확인

- 공유한 뒤 1시간, 24시간, 7일에 플랫폼별 유입을 보고 조회 시각과 함께 사용자에게 알린다. 시점마다 쓰임이 달라서다: 첫 반응은 문구 수정, 하루 누적은 재공유, 한 주 누적은 다음 주제를 정하는 데 쓴다.
- 조회 명령, 인증, 호출 한도는 블로그 저장소 `AGENTS.md`의 "방문 데이터 조회" 절이 정본이다.
- 1시간 시점은 Clarity로, 24시간과 7일은 GA4로 본다.
- 캠페인 인자에 글의 slug를 넘기면 그 글의 공유 유입만 나온다.
- 봇 세션만 있는 경로는 사람 방문이 아니므로 보고할 때 따로 표시한다.
- 조회가 인증이나 권한 오류로 실패하면 다른 계정이나 키로 우회하지 말고 오류 문구를 사용자에게 알린다.
