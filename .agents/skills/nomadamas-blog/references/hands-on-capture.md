# 직접 써 보기와 캡처

## 목차

- 시연 환경
- 모델과 비용
- 터미널 앱 캡처: tmux
- 명령 캡처: VHS
- 웹 화면 캡처: headless Chrome
- 로그인한 브라우저와 앱 창
- 비교 대상 서비스 직접 써 보기
- 사용 과정 영상
- 측정값으로 움직이는 그림
- 이미지 구하기
- 이미지 편집
- 표지와 설명 그림

강조 색의 뜻, 캡션에 적을 날짜와 버전, 잘라낼 개인정보, 시연 폴더 위치는 이 저장소의 플레이북 8절(시연과 캡처)이 정본이다. 이 문서는 그 결정을 지키는 방법과 도구의 함정을 다룬다.

## 시연 환경

- 도구는 시연 폴더 범위로만 설치한다. 플러그인이면 그 폴더만 쓰는 범위(local scope)로, 패키지면 폴더 안에 설치한다. 전역 설치가 꼭 필요하면 먼저 승인받는다.
- 설치 전후로 전역 상태를 목록으로 떠서 비교한다. 대상은 에이전트 스킬 폴더들, 전역 패키지 목록, 도구의 전역 설정 파일이다. 도구 지침이 에이전트에게 전역 설치를 시키는 경우가 있다.
- 전역에 쓰는 명령은 시연 세션의 권한 설정(deny)으로 막고, 막힌 기록을 세션 로그에서 확인해 PR 검증 항목에 적는다.
- 도구가 설정 위치를 바꾸는 환경변수(예: `<TOOL>_HOME`)를 지원하면 시연 폴더 안으로 돌린다. 사용자의 전역 설정이 시연 결과에 섞이지 않는다.
- 실제 개인 데이터로 먼저 돌려 결과 모양(출처 표기, 잡음이 섞이는 방식)을 본 뒤, 같은 모양의 합성 데이터를 만드는 스크립트를 작업 폴더에 둔다. 개인 데이터 사본은 시연이 끝나면 휴지통으로 옮긴다.
- 브라우저 편집기처럼 화면을 조작하는 단계는 사용자에게 넘기지 않고 Playwright로 직접 조작한다. 사용자가 할 일은 권한 분류기가 막은 단계뿐이다.
- 연결 도구는 기본 동기화 대상을 먼저 확인한다. 기본값이 사용자의 실제 계정(메신저, 메일)을 읽는 도구가 있다. 합성 자료만 읽도록 대상을 고정하고, 실제 계정 경로에 닿으면 멈추는 가드를 둔다.
- 실제 형식의 공개 문서가 필요하면(HWP 공문 등) 공공누리 제1유형 자료를 쓰고 글의 참고 자료에 출처를 적는다. 나머지는 합성 자료로 채운다.
- 알릴 도구의 출시본 버그가 시연을 막으면 플레이북 8절의 결정대로 고쳐 PR을 보내고 고친 빌드로 잰다. 시연 폴더 README에 빌드 출처(PR 번호, 커밋)를 적는다.
- 권한 분류기가 막은 명령(에이전트 중첩 실행, 새 터미널 열기)은 우회하지 않는다. 실행 스크립트를 만들어 사용자에게 `! bash <스크립트>` 실행을 부탁한다.

## 모델과 비용

- 시연 모델은 플레이북 8절의 기준으로 고르고, 고른 이유와 조회일을 작업 폴더 README에 적는다.
- 유료 API는 요청과 토큰을 기록하는 로컬 프록시를 앞에 두고, 호출마다 태그를 붙여 비용을 잰다. 예시 구현이 이 저장소에 있으면 그 파일을 먼저 읽고, 없으면 같은 역할의 격리 프록시를 만든다.
- API 키는 `agents-env run <KEY>@<tag> -- <명령>`으로 그 프로세스에만 넣는다.
- 유료 키는 승인을 묻기 전에 무료 조회로 살아 있는지와 남은 한도를 본다. 죽은 키로 승인받으면 첫 호출이 401로 실패한 뒤 승인을 다시 받아야 한다. OpenRouter는 아래처럼 본다. 응답의 `label`에는 키 일부가 들어 있어 필요한 칸만 뽑는다.

    ```bash
    agents-env run OPENROUTER_API_KEY@<tag> -- curl -s -m 20 https://openrouter.ai/api/v1/auth/key \
      -H 'Authorization: Bearer {{OPENROUTER_API_KEY}}' | jq -c '.error // (.data | {usage, limit, limit_remaining})'
    ```

- 같은 질문을 여러 번 돌려 답이 흔들리면 그 편차를 글에 적는다.
- 도구끼리 비교하면 같은 경로(API끼리, 화면끼리)로 재고 어느 경로인지 적는다. 같은 도구도 API와 화면의 답이 다를 수 있다.

## 터미널 앱 캡처: tmux

Claude Code, Codex 같은 전체 화면 터미널 앱은 전용 tmux 서버에서 실제로 돌리고, 화면을 ANSI로 떠서 `scripts/render_terminal.py`로 PNG를 만든다.

```bash
env $(env | grep -oE '^CLAUDE[A-Z0-9_]*' | sed 's/^/-u /') \
  tmux -L demo new-session -d -s demo -x 116 -y 44 -c /Users/Shared/<slug>-demo -e COLORTERM=truecolor
tmux -L demo send-keys -t demo "claude --safe-mode --permission-mode manual --model <모델>" Enter
tmux -L demo send-keys -t demo -l "<한국어 질문>"
tmux -L demo send-keys -t demo Enter
tmux -L demo capture-pane -p -e -t demo > caps/01-<이름>.ansi
```

- 첫 줄은 작업 세션에서 물려받은 `CLAUDE`로 시작하는 환경 변수를 지우고 tmux 서버를 띄운다. 독자가 새 터미널을 연 상태와 맞추려는 것이다. 띄운 뒤 `tmux -L demo show-environment -g | grep -c '^CLAUDE'`가 0인지 본다. 예시 스크립트가 이 저장소에 있으면 그 파일을 먼저 읽는다.
- `--safe-mode`는 CLAUDE.md, 개인 스킬, 설치한 플러그인, 훅, MCP 서버를 끄고 권한 설정은 그대로 둔다(`claude --help`). 독자의 새 Claude Code에는 이것들이 없다.
- 소개할 대상이 스킬이나 플러그인이면 `--safe-mode`가 그것까지 끄므로 빼고, 캡처마다 개인 스킬이나 훅의 출력이 섞였는지 본다.
- 권한을 매번 묻는 모드의 이름은 버전마다 바뀐다(2.1.292는 `manual`). `claude --help`의 `--permission-mode` 선택지를 먼저 본다.
- API 키가 필요하면 tmux 서버 자체를 `agents-env run <KEY>@<tag> -- env -u ... tmux -L demo new-session ...`으로 띄운다. 창 안에서 명령을 `agents-env run`으로 감싸면 출력이 중간에 멈춘다.
- `-L`로 전용 서버를 쓰면 사용자의 tmux 세션을 건드리지 않는다. 창 크기(`-x`, `-y`)가 캡처 폭과 높이가 된다.
- 한글은 `send-keys -l`로 글자 그대로 보내고 Enter는 따로 보낸다. 자동완성이 붙는 입력창은 한 글자씩 보낸다.
- 입력하기 전에 화면에 권한 확인 창이 없는지 본다. 숫자가 든 문장을 보내면 떠 있던 권한 창의 선택지가 눌린다.
- 권한 창은 명령 내용을 읽고 안전할 때만 승인한다. 전역 설치나 삭제가 보이면 멈추고 사용자에게 알린다. 승인 전 화면도 떠 두면 글에 권한 확인 장면으로 쓸 수 있다.
- 신뢰 확인 창은 선택지를 읽고 고른다. 기본 선택이 허용 목록을 적용하지 않는 쪽일 수 있다.
- 질문 사이에는 `/clear`를 보낸다.
- 응답이 끝났는지는 화면을 몇 초마다 떠서 완료 표시를 찾아 판단한다. 표시 문구는 버전마다 달라서 첫 응답에서 확인한다.
- 렌더링 전에 `render_terminal.py rows <파일>`로 행 번호를 보고 자를 구간과 강조할 행을 고른다.

## 명령 캡처: VHS

한 줄짜리 명령과 출력은 VHS tape로 돌린다. `Output logs/NN.txt`로 텍스트 로그를 함께 남겨 강조 위치와 본문 인용의 근거로 쓴다.

- 한글 글자 사이가 벌어지면 `Set FontFamily "D2Coding"`을 쓴다.
- 프롬프트를 기다릴 때는 `Wait@60s /^\$$/`처럼 끝 공백이 없는 패턴을 쓴다. 프롬프트 줄은 끝 공백이 잘려 `/^\$ $/`가 맞지 않는다.
- `Screenshot` 앞에는 `Wait+Screen@<초>s /<패턴>/`으로 출력이 뜬 것을 확인한다. 뒤에는 `Sleep 2s` 이상을 둔다. 뒤 Sleep이 없으면 PNG가 써지지 않고, 곧바로 `Hide`나 `clear`가 오면 빈 화면이 찍힌다.
- 따옴표가 복잡한 명령은 셸 스크립트로 빼고 tape에서는 그 스크립트를 부른다. tape 안의 이스케이프는 쉽게 깨진다.
- Claude Code 같은 전체 화면 앱은 VHS보다 tmux가 안정적이다.

## 웹 화면 캡처: headless Chrome

```bash
python3 <skill-dir>/scripts/render_html.py <주소> caps/<이름>.png --width 1280 --height 2400 --wait-ms 6000
```

- headless Chrome은 PNG를 쓴 뒤에도 끝나지 않을 때가 있어 직접 부르면 명령이 멈춘다. `render_html.py`는 PNG가 끝까지 써지면 Chrome을 끝낸다.
- 웹 캡처는 처음부터 2배율로 찍는다(`render_html.py` 기본값, gstack browse는 `viewport 1280x800 --scale 2`). 1배율은 글에서 흐려 다시 찍게 된다. 편집 좌표는 CSS 픽셀로 잡고 2배로 환산한다.
- 로그인이 필요 없는 공개 페이지(GitHub 저장소 첫 화면 등)는 이 방법으로 찍는다. 로그인 상태가 없어 아바타와 계정 메뉴가 찍히지 않는다.
- 앵커(`#절`)나 스크롤로 특정 위치를 찍으면 검게 나온다. 긴 창으로 전체를 찍고 잘라낸다.
- 창 폭은 약 500px 아래로 줄지 않는다. 폰 폭의 가로 넘침은 `scripts/check_phone_width.py`로 재고, 화면은 `chrome-devtools emulate`로 찍는다(`publish.md` 빌드와 미리보기 절).
- 로컬 서버를 띄울 때는 포트가 비었는지 먼저 확인한다(`lsof -iTCP:<포트> -sTCP:LISTEN`). 다른 세션이 띄운 서버는 끄지 않는다. 서버가 조용히 실패하면 다른 서버의 페이지가 찍힌다.

## 로그인한 브라우저와 앱 창

- 로그인 상태가 필요한 화면은 전역 브라우저 규칙이 정한 도구로 띄워 찍고, 아바타, 계정 메뉴, 사용자 이름을 잘라낸다.
- macOS 앱 창은 `screencapture -l<창 번호> -o -x out.png`로 찍는다. 창 번호는 CGWindowList로 찾는다. 다른 Space에 있는 창은 전체 창 목록 옵션으로 찾는다.
- 데스크톱 전체를 찍지 않는다. 다른 창의 개인 정보가 함께 찍힌다.

## 비교 대상 서비스 직접 써 보기

비교하는 웹 서비스는 무료 플랜에 시연과 같은 합성 자료를 넣고 직접 써 본다. 같은 조건의 결과 화면은 도움말 이미지보다 차이를 잘 보여 준다.

- 로그인은 전역 브라우저 규칙이 정한 도구(Aside REPL)로, 조직 공용 계정으로 한다. 결제와 유료 플랜 체험은 승인 없이 시작하지 않는다.
- 찍을 화면: 같은 부탁으로 나온 결과, 부분 수정 전후, 무료 플랜의 내보내기 제한. 본문에서 비교하는 항목마다 화면 하나를 맞춘다.
- 결과의 수치를 원자료와 맞춰 보고 캡션에 적는다. 틀린 값이 있으면 그대로 보인다.
- 직접 써 보니 도움말과 다르면(예: 베타 기능이 이미 열려 있음) 비교표를 실제 동작에 맞춘다. 우리 도구에만 있다고 쓴 기능이 상대에게도 있으면 차별점에서 뺀다.
- Aside `openTab`으로 연 탭은 호출이 끝나면 닫힌다. 여러 단계 조작은 한 호출 안에서 끝내거나, 사용자 탭에 `attachBrowserTab`으로 붙는다.
- 붙어 있던 탭이 사라질 수 있다. 작업 주소(세션, 문서 URL)를 적어 두고 다시 연다.
- 마우스 좌표는 CSS 픽셀이다. 레티나 스크린샷은 두 배 크기라 이미지 좌표를 그대로 쓰면 빗나간다. 요소 위치는 `getBoundingClientRect`로 구한다.
- 생성이 몇 분씩 걸리면 대기 루프로 세션을 묶지 않는다. 다른 단계(원고, 영상 편집)를 하다가 한 번씩 확인한다.

## 사용 과정 영상

도구를 어떻게 쓰는지는 영상이 가장 잘 보여 준다. 공식 데모 영상이 있으면 쓰고, 없거나 이 글의 시연과 다르면 직접 녹화한다.

- 브라우저 화면은 Playwright `recordVideo`로 녹화하고, 단계마다 녹화 시작 기준 시각을 로그에 남긴다. 편집할 구간을 그 시각으로 자른다.
- AI 응답을 기다리는 구간은 ffmpeg `setpts`로 빠르게 돌리고, 배율을 화면에 안내 문구로 얹는다. 이 환경의 ffmpeg에 `drawtext`가 없으면 안내 문구를 PNG로 만들어 `overlay`로 얹는다.
- 출력은 h264 mp4(`-crf 24 -movflags +faststart`, 폭 1280)와 첫 화면 jpg로 만들어 블로그 저장소 `public/videos/<slug>/`에 둔다. GIF는 용량이 크고 멈추거나 되감을 수 없어 쓰지 않는다.
- 본문에는 `<video src poster controls playsinline preload="metadata" width="100%">`로 넣고 `aria-label`에 화면에서 일어나는 일을 적는다. `muted`는 소리 없는 화면 녹화에만 붙인다. 원본에 소리가 있는 영상(현장 촬영, 공식 데모)은 플레이북의 영상 결정대로 소리를 살리고 캡션에 "소리 있음"을 적는다.
- 소리를 살릴 때는 넣기 전에 그 구간을 `stt` 스킬로 전사해 무엇이 들리는지 본다. 편집할 때 ffmpeg `loudnorm`으로 음량을 맞추고 aac로 넣는다. 공식 영상은 원래 소리를 그대로 옮긴다.
- 캡션에 길이, 빠르게 돌린 배율과 실제 걸린 시간을 적는다. 캡처와 따로 녹화해 문구나 시간이 다르면 그 사실도 적는다.
- 미리보기에서 영상 응답(200, `video/mp4`)과 재생 막대가 보이는지 확인하고, `check_playback.py`로 다른 페이지에서 링크로 들어왔을 때도 재생되는지 본다(`publish.md` 빌드와 미리보기 절).

## 측정값으로 움직이는 그림

속도처럼 시간이 핵심인 차이를 플레이북 결정대로 실제 걸린 시간대로 움직여 보일 때의 방법이다.

- 측정할 때 항목마다 시각을 로그에 남긴다(요청을 보낸 시각, 첫 토큰, 응답이 끝난 시각). 걸린 시간만 남기면 그 사이의 움직임을 다시 그릴 수 없다.
- 그림은 HTML 한 장에 `window.render(t)`를 두고, t초의 화면을 측정 로그에서 계산해 그린다. 시계로 재생하지 않고 t를 받아 그리면 프레임마다 같은 화면이 나온다.
- 프레임은 `chrome-devtools`로 찍는다. `new_page --background`로 열고 `emulate --viewport <폭>x<높이>x2`로 크기를 고정한 뒤, 프레임마다 `evaluate_script "() => window.render(<t>)"`와 `take_screenshot`을 부른다. 예시 스크립트가 이 저장소에 있으면 그 파일을 먼저 읽는다.
- 시작 전과 끝난 뒤에 멈춘 화면을 둔다. 끝 화면은 결과를 읽을 수 있게 2초 이상 둔다. 오래 걸리는 쪽을 빠르게 돌린 구간은 배율을 화면에 적는다.
- 프레임은 ffmpeg로 mp4와 포스터 jpg로 묶는다. 출력 형식과 본문에 넣는 법은 사용 과정 영상 절과 같다.
- 재지 못한 시각(토큰이 하나씩 나온 시각 등)은 지어내지 않는다. 고르게 나눠 그리고, 그 사실을 캡션과 작업 폴더 README에 적는다.
- 지난 측정의 로그로 시각을 다시 계산했으면, 시각을 기록한 새 측정 한 번에 같은 계산을 돌려 차이를 확인한다. 원본 로그와 계산 스크립트는 작업 폴더에 함께 둔다.

## 이미지 구하기

무엇을 넣을지는 그 절에서 보여 줄 것으로 정한다(플레이북 6절). 직접 찍은 화면이 맞는 절도, 공식 이미지가 맞는 절도 있다. 공식 자료와 그림을 구할 때는 아래 순서로 찾는다. 다시 그리거나 생성한 그림은 실제 제품과 달라질 수 있다.

1. 공식 이미지: 소개하는 저장소의 README와 문서, 공식 사이트, 공식 블로그와 보도자료에 있는 이미지.
2. 로고: 그 회사나 프로젝트가 직접 배포한 로고(브랜드 가이드, 보도자료 키트, 공식 GitHub 조직 이미지). 찾지 못하면 react-icons의 브랜드 아이콘(`react-icons/si`)을 쓰고 PR 리뷰 포인트에 적는다.
3. 아이콘: 파일, 폴더, 메일 같은 일반 아이콘은 react-icons에서 고른다. 이름은 `https://react-icons.github.io/react-icons/search`에서 확인한다.
4. 생성: 위에서 구할 수 없는 그림(표지 배경, 개념 그림)만 Codex CLI의 이미지 생성으로 만든다.

찾을 때 쓰는 도구:

- `tvly search "<제품명> brand logo" --include-images --json`: 검색 결과와 함께 이미지 주소를 준다. 공식이 아닌 사이트의 이미지도 섞이므로 주소의 도메인을 보고 고른다. `--include-domains <공식 도메인>`으로 좁힐 수 있다.
- 키가 없으면 호출 수 제한이 걸린다. 키는 `agents-env run TAVILY_API_KEY@<tag> -- tvly ...`로 넣는다.
- Aside CLI: 스크립트로 그리는 페이지나 로그인이 필요한 페이지에서 이미지를 찾을 때 쓴다. 쓰기 전에 `aside guide`를 읽는다.
- 웹 검색: 브랜드 가이드와 보도자료 키트 페이지를 찾는다.

react-icons는 설명 그림 HTML에 넣을 SVG로 뽑는다. 패키지는 임시 폴더에 설치해 작업 폴더에 `node_modules`가 생기지 않게 한다.

```bash
T=$(mktemp -d) && cd "$T" && bun add react react-dom react-icons
mkdir -p <작업 폴더>/edit/icons
bun -e 'import {createElement as h} from "react"; import {renderToStaticMarkup as r} from "react-dom/server"; import {LuFolder} from "react-icons/lu"; console.log(r(h(LuFolder, {size: 48})))' > <작업 폴더>/edit/icons/folder.svg
```

Codex 이미지 생성은 파일을 쓸 수 있게 작업 폴더에서 돌리고, 끝나면 파일이 실제로 생겼는지 확인한다.

```bash
mkdir -p <작업 폴더>/edit/gen
codex exec -s workspace-write --skip-git-repo-check -C <작업 폴더>/edit \
  "<그림 설명>. 이미지를 하나 생성해 /bin/cp로 gen/<이름>.png에 복사하고, 파일을 찾지 말고 바로 끝내라." \
  < /dev/null > <작업 폴더>/edit/gen/<이름>.log 2>&1
file <작업 폴더>/edit/gen/<이름>.png
```

- Codex가 저장했다고 답하고 종료 코드가 0이어도 파일이 없을 수 있다. 없으면 로그 머리의 `session id`로 `~/.codex/generated_images/<session id>/`에서 찾는다. 한 번에 여러 장이 생기기도 하니 열어 보고 고른다.
- 복사는 `/bin/cp`로 시킨다. `cpq` 같은 셸 별칭은 Codex의 비대화형 셸에 없어 복사가 실패한다.
- 입력을 `/dev/null`로 닫는다. 열어 두면 입력을 기다리며 멈춘다.
- 프롬프트에 "파일을 찾지 말고 바로 끝내라"를 넣는다. 빼면 만든 파일을 찾아다니다 시간 초과가 난다.
- 여러 장은 동시에 3개 이하로 돌린다. 더 많이 돌리면 간헐적으로 시간 초과가 난다.
- 한 장에도 Codex 사용량이 적지 않게 드니 필요한 그림만 만든다.

소개 대상의 사진(공간, 단체, 행사, 작품):

- 웹에서 찾는다. 공식 게시물과 사이트 앨범, 보도자료, 기사 본문 순으로 본다. 로컬 폴더는 사용자가 경로를 준 경우에만 본다.
- 페이지를 내려받아도 사진이 안 나오면 브라우저로 렌더링해서 다시 찾는다(headless Chrome의 `--dump-dom`이나 Aside). 본문을 스크립트로 그리는 페이지가 많다.
- 후보를 모두 열어 본 뒤 고른다. 처음 찾은 한 장으로 정하면 더 나은 사진을 놓친다.
- 권리는 공식 배포 이미지, 출처 표시로 쓸 수 있는 라이선스(Wikimedia Commons의 CC 등), 언론과 방송 사진 순으로 고른다. 언론과 방송 사진은 캡션에 저작권자를 적고 PR 리뷰 포인트에 올린다.

행사 글의 공식 자료:

- 행사 공식 사이트의 메뉴(전시 배치도, 참가기업, 프로그램, 자주 묻는 질문)를 모두 열어 공식 이미지 목록을 작업 폴더 README에 만들고, 자료마다 쓸 절을 적는다. 배너 하나를 찾으려고 훑으면 이미 받아 둔 배치도도 쓰지 않고 넘어간다.
- 위치를 말하는 절은 공식 배치도에 그 자리를 표시해 쓴다. 팀이나 회사의 구역 번호는 배치도 아래 참가사 목록에서 이름으로 찾는다. 표시를 그리는 스크립트는 작업 폴더 `edit/`에 둔다.
- 지난 회차 사진(첫 화면 슬라이드에 섞여 있다), 폼을 내야 받는 자료, 근거 표와 다른 시간이나 장소가 적힌 포스터는 쓰지 않는다.

기록:

- 받거나 만든 이미지마다 출처 주소(생성이면 프롬프트)와 날짜를 작업 폴더 README에 적는다.
- 생성한 이미지는 PR 리뷰 포인트에 적는다. 공식 이미지처럼 보이게 쓰지 않는다.

## 이미지 편집

- 전체 화면 터미널 앱은 줄 간격이 좁아 테두리 상자가 옆 줄 글자를 긋는다. 옅은 배경과 왼쪽 막대로 강조한다(`render_terminal.py`의 `kind: bar`).
- 라벨은 짧은 알약 모양으로 붙이고 가리키는 줄과 겹치지 않게 둔다.
- 잘라낼 것: 계정 아바타, 사용자 이름이 든 경로, 개인 폴더 목록, 토큰이 든 주소.
- 현장 사진의 관람객 얼굴 흐림과 아이폰 HDR 영상의 SDR 변환은 이전 글 작업 폴더의 스크립트부터 찾아 쓴다. 같은 스크립트를 다시 쓰게 되면 이 스킬의 `scripts/`로 올리자고 제안한다.
- 편집한 이미지는 전부 Read로 열어 눈으로 확인한다.

## 표지와 설명 그림

- 표지는 1200x630 HTML을 만들어 `render_html.py <html> <이미지 폴더>/00-cover.png --width 1200 --height 630`으로 찍는다. 이전 글의 표지를 먼저 열어 같은 형식으로 맞추고 frontmatter `ogImage`에 연결한다. 자동 생성 카드는 긴 제목이 어색하게 줄바꿈된다.
- 구조 그림과 시연 상황 그림도 HTML로 만들어 `render_html.py <html> <png>`로 찍는다. 높이를 주지 않으면 아래 여백을 잘라 준다. 연결되는 서비스는 공식 로고로 보인다(이미지 구하기 절). 원본 HTML과 렌더 명령을 작업 폴더에 둔다.
- 그 글에만 필요한 단계(그림 속 값과 원고 대조, 아이콘 끼워 넣기)만 작업 폴더 스크립트로 두고 찍기는 `render_html.py`를 부른다. 글마다 Chrome 호출을 새로 짜면 Chrome이 끝나지 않는 문제를 매번 다시 겪는다.
- 외부 이미지(저장소 README 대표 이미지 등)에 실존 인물 사진, 브랜드 로고, 워터마크가 있으면 PR 리뷰 포인트에 적어 사용자가 판단하게 한다.
